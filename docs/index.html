Project guide

RAGForge

RAGForge answers questions about PDF documents and shows its work: page citations, the passages each answer came from, a live quality score and, in the hosted version, what the answer cost. This page covers the whole project: the branches, the workflow, the settings, the evaluation, the decisions and how to run it.

Overview

RAGForge started as a learning project with two goals: build a retrieval-augmented generation (RAG) system, and learn how to evaluate one properly. It produced three kinds of work, kept on separate branches: a lab that measured components against a hand-built test set, a local free product, and a hosted bring-your-own-key product.

Every version does the following.

  • Answers questions about uploaded PDFs, including scanned pages (read with OCR), with page citations.
  • Searches two ways at once, by meaning (vectors) and by keywords (BM25), fuses the results, then re-sorts the best candidates with a reranker before an answer model writes the response.
  • Shows the evidence: the retrieved passages and their scores sit next to each answer.
  • Scores itself with the RAG triad (is the retrieved text on topic, is the answer backed by it, does it answer the question). This needs no reference answers, so it works on any document.
  • Screens every question for prompt injection, and refuses rather than invents.
  • Remembers the last few turns to handle follow-ups, and answers repeated questions from a private session cache.
  • Takes thumbs up or down on every answer. A thumbs down asks what was wrong and offers a better second try.

The hosted version adds usage and cost tracking, a choice of provider and model per component, upload limits and privacy handling for a public server.

Low context relevance with high groundedness means search brought noisy passages and the answer stayed faithful to them. High context relevance with low groundedness means the model added claims its sources do not support.

Evaluation

A RAG system can fail by retrieving the wrong passages or by writing a poor answer from good ones. Evaluation exists to tell those apart.

Component evaluation

Against a golden set of 45 questions over three papers (LoRA, QLoRA, "Attention Is All You Need"). Each question has a reference answer and the pages that contain it. Compares versions of each part. Offline, on demand.

RAG triad

Needs no reference answers. Scores every live answer for relevance, grounding and on-topic retrieval, so it works on any uploaded document.

StageQuestion it answersMetrics
RetrieverDoes search find the right pages, and near the top?Recall@K, Precision@K, Hit Rate@K, MRR
RerankerDoes re-sorting move the right page up?The same four, with and without
ChunkingDo context notes help?The same four, per method
GeneratorIs the answer faithful, relevant and correct?Faithfulness, answer relevancy, correctness, similarity, context recall
Generator, oracleSame, handed the right pagesThe same five; isolates the answer model from search
RAG triadDoes the whole pipeline hang together?Context relevance, groundedness, answer relevance
LatencyWhere does the time go?Seconds per stage

Safeguards in the method.

  • A different model judges than answers, so no model grades itself. The same answers scored 0.97 for correctness under a lenient judge and 0.80 under a stricter one, so only compare runs that used the same judge.
  • Relevance is judged by page, so chunking strategies can be compared on equal terms. Scores are slightly generous as a result.
  • Settings were tuned on two thirds of the questions and checked on the rest. Near-ties (within 0.01 MRR) go to the faster option.
  • With 45 questions, one question moves a score by about 0.02, so gaps of a few hundredths are noise.

The triad is the slowest part of a turn and a large share of its cost, because each metric makes several judge calls. A full run on OpenAI cost about $1.3 for the stages plus about $0.7 once to build the index, and took about 100 minutes. Results are saved so they never need to be paid for again.

What else was found

  • A reranker is the biggest single gain. Locally, hybrid MRR went from 0.74 to 0.92; the right page was usually already retrieved, just not first.
  • A purpose-built cross-encoder beat a small chat model as reranker. Chat-model rerankers made local retrieval worse than no reranker at all.
  • Bigger rerankers were not better. Hosted gpt-4o reached MRR 0.89 against 0.86 for gpt-4o-mini, at far higher cost.
  • Context notes helped single searches but not the reranked pipeline. Plain chunks scored MRR 0.91 against 0.87 with notes, and the notes add a one-time indexing cost. They are still on by default.
  • Most of the faithfulness gap is retrieval. Faithfulness was 0.71 with retrieved chunks and 0.94 with the golden pages.

Privacy and safety

ConcernHow it is handled
API keysHeld in session memory only. Never written to disk or logged.
Uploaded PDFsDeleted as soon as they are indexed.
Index and answer cacheLive in a private per-session folder in the system temp directory. Removed when documents are replaced, when the session ends (reload, closed tab, new session) and on every server restart.
RatingsStored with the session cache and deleted with it. Nothing about a user persists.
Prompt injectionEvery question passes the input guard before anything is retrieved.
Invented answersThe answer prompt refuses rather than invents and never uses outside knowledge.
Oversized uploads20-page total and 25 MB per file, checked on the page and again before indexing, so an oversized file never reaches a model.
Stalled providersEvery model request has a 60 second timeout and is retried twice.
Where documents goHosted: to the providers the user chose, who also bill them. Local: nowhere.
No login or rate limit. Costs fall on each user's own key, but anyone who can reach the page can use the server's CPU and memory. If it is not meant to be public, put it behind a login (for example Caddy basic_auth), a VPN or an IP allow-list.

Setup

The main branch has no code, so clone one of the code branches. Common to all: install uv. Scanned PDFs also need Tesseract (brew install tesseract or apt install tesseract-ocr). The web app opens at localhost:8501.

Hosted version ragforge_api

git clone -b ragforge_api https://github.com/janarddansarkar/RAGFORGE.git && cd RAGFORGE
uv run streamlit run src/app.py
  • The first run installs the packages. No model is downloaded.
  • Pick a provider and model for each component in the sidebar and paste a key for each provider you chose. One OpenAI key is enough to start.
  • Upload PDFs (20 pages in total) and click Ingest. The first ingest is slow because every chunk gets a context note.
  • Changing a provider or model resets the documents; click Ingest again.
  • One question from the command line: uv run python src/triad.py your.pdf "your question".

Local version dev

git clone -b dev https://github.com/janarddansarkar/RAGFORGE.git && cd RAGFORGE
./setup.sh    # installs Ollama if needed, the packages and the models
./run.sh      # starts the web app
  • Default models are about 14 GB and want about 24 GB of RAM. On a smaller machine switch the answer model to gemma3:4b (about 8 GB of models, 16 GB of RAM) in the two config files and run setup again.
  • The first question downloads the reranker (about 1 GB). After that it works offline.
  • Command line: uv run python src/rag.py documents/LoRA.pdf "What rank r does LoRA use?"

Evaluation lab offline-eval

git clone -b offline-eval https://github.com/janarddansarkar/RAGFORGE.git && cd RAGFORGE
ollama pull bge-m3 qwen2.5:3b mistral:7b
uv sync
uv run python eval/find_best.py --limit 5 --no-save    # quick smoke test, writes nothing
  • The full search takes hours. --stages runs only some stages, --no-save writes nothing, --skip-missing leaves out models you have not pulled.
  • It checks every needed model is downloaded first and prints the exact commands for any that are not.

Running the hosted evaluation

uv run python eval/run_provider_eval.py openai --limit 10   # cheaper trial
uv run python eval/run_provider_eval.py openai              # everything, about 100 minutes
uv run python eval/make_report.py                           # rebuild the report from saved data, free

It costs real money, so read the saved results first. A free-tier Gemini key (5 requests a minute) cannot complete it. Unit tests need no keys: uv run pytest.

Deploying the hosted version on a server

StepWhat to do
NeedsAbout 2 GB RAM (around 560 MB for one user, plus about 160 MB for the scoring library; 1 GB works only with swap), about 1 GB disk, git, curl, tesseract-ocr, and a domain name for HTTPS.
1. Install and runClone the branch and start the app listening only on 127.0.0.1, so it is not directly reachable from outside.
2. Keep it runningA systemd service with Restart=always and PrivateTmp=true. The private temp folder is deleted when the service stops, a second guarantee that no upload survives a restart.
3. HTTPSA reverse proxy such as Caddy gets and renews a certificate and passes the WebSocket Streamlit needs. Open only SSH, 80 and 443; keep 8501 closed. Users type API keys into the page, so never serve it over plain HTTP.
4. Updategit pull and restart the service.

Full commands and the service file are in docs/DEPLOY_VPS.md on the ragforge_api branch. It was tested locally with a real server and browser, not on a VPS. Scanned PDFs are slow on a small server because OCR runs on the CPU.

Known limits

  • The golden set is small: 45 questions over three research papers.
  • Hosted quality was measured with OpenAI only. Gemini, Cohere and Anthropic were exercised end to end but not scored on the full set.
  • Costs shown are estimates from a price list; the provider's bill is the truth.
  • No login or rate limit in the hosted app.
  • Only PDFs are accepted; standalone images are not.
  • If a connection drops and the private session folder is cleaned up meanwhile, the app asks the user to upload again.
  • Claude models "think" before answering and the thinking counts against the token limit. The app asks for minimal thinking and adds 512 tokens of headroom; otherwise some answers came back empty.
